# R4 서버 연동 (팀원 그림 생성 서버)

말잇다 v2의 지원자용 **그림 만들기**는 팀원이 만든 R4 서버(FastAPI, `malitda-backend-r4-live`, 2026-10-24 전달본)를 거쳐 그림을 만든다. 그림 생성 키는 서버의 `backend/.env`에만 있고 앱에는 없다.

## 서버에 적용할 변경: `meaning-generation.patch`

전달본 서버는 학생 그림체를 반영한 생성을 고정 장면 3개(산책·말하기·풍선)로만 지원한다. 말잇다 v2는 지원자가 등록한 뜻 문장으로 그림을 만들어야 해서, `/api/generate`에 선택 항목 `meaning`을 추가했다. 기존 요청 형식은 그대로 동작한다.

- `meaning`을 보내면 `profile_id`·`profile_revision`이 필수이고 `scene`은 비워야 한다(어기면 422).
- 학생의 저장된 그림체와 그 그림체의 기준 그림을 쓰고, 뜻 문장을 그림 지시문에 넣는다.
- 결과는 앱으로만 돌려주고 서버 후보 저장소(장면별 후보)에는 넣지 않는다. 앱이 저장하고 학생 확인을 거친다.
- 버전이 바뀐 요청은 공급자 호출 전에 409로 거부한다(기존 규칙과 같음).

적용과 확인(서버 폴더 `malitda-backend-r4-live`에서):

```powershell
git apply -p1 <말잇다 저장소>\docs\r4-server\meaning-generation.patch
copy <말잇다 저장소>\docs\r4-server\test_meaning_generation.py backend\
.\.venv\Scripts\python -m pytest backend
```

2026-10-24 확인: 전달본 원본에 패치가 그대로 적용되고, 기존 테스트 40개 + 새 테스트 3개 = 43개 통과.

## 앱 쪽

| 파일 | 역할 |
|---|---|
| `data/ai/R4Client.kt` | 서버 상태 확인, 학생 그림체 동기화(revision), 뜻 그림 생성, 그림체 미리보기 |
| `domain/ArtStyles.kt` | 그림체 10종(서버와 같은 ID), 서버 응답 → 안내 문구, 그림체 동기화 판단 |
| `ui/v2/U15ArtStyle.kt` | 설정 › 그림체 선택(기본 2열, 큰 글씨 1열) |
| `src/debug/AndroidManifest.xml`, `res/xml/r4_network_security.xml` | 디버그 전용 인터넷 권한, 127.0.0.1만 평문 허용 |

팀원 서버 규칙을 그대로 따른다: 비용 동의와 생성 버튼 분리(생성할 때마다 다시 동의), 쓰기 요청마다 서버 토큰을 새로 받음, 결과가 불확실한 요청(502·504)은 자동으로 다시 보내지 않음.

## 확인 방법 (유료 호출 없이)

팀원 테스트와 같은 방식으로 가짜 생성기를 붙여 서버를 띄우면 비용 없이 앱 흐름 전체를 볼 수 있다. 2026-10-24에 에뮬레이터에서 확인한 것: 그림체 10종 미리보기, 수채화 선택이 서버에 반영, 동의 → 생성 → 폼에 그림 반영, 생성 뒤 동의 해제, 점검 모드 안내, 서버 꺼짐 안내. 실제 OpenRouter 생성은 키가 없어 확인하지 않았다.

## 남은 일

- 운영 배포: 서버가 PC 안(127.0.0.1)에서만 열리고 `X-Demo-Token`은 인증이 아니다. 팀 배포본에서 쓰려면 HTTPS·사용자 인증이 필요하다.
- 서버의 키 변경 API(`POST /api/settings`)는 로컬 개발용으로만 둔다.
- 서버 기본 생성 크기는 정사각형(1024×1024)이고 앱 카드는 가로형이라 가운데가 잘려 보인다. 지시문에 "주인공을 가운데에"를 넣어 두었다.
