# 말잇다 0.3.2 서비스 구성·근거·인계보고서

기준일: 2026-10-27. 대상은 현재 Android 0.3.2 작업본과 같은 Figma 파일의 추가 설계 섹션이다. 최종 앱 소스는 167f86f이며 APK와 검수 범위는 verification.json에 연결했다. 기능이 코드에 연결된 사실, 화면에서 확인한 사실, 실제 사용자에게 효과가 있는지는 각각 구분한다.

## 1. 현재 결론

말잇다는 평소 쓰는 표현을 등록된 뜻과 연결하고, 당사자가 그림·문장·소리로 확인한 뒤 전달하는 서비스다. 이번 변경은 이 흐름을 홈·내 표현·함께 관리·설정의 네 탭으로 정리하고 첫 사용 안내와 지원자 관리 경계를 보완했다. 등록된 표현에서 후보를 찾는 기능을 모든 발화의 의도를 이해하는 AI로 설명하지 않는다.

현재 소스에서 네 탭, 실제 상황 태그 필터, 세 쪽 온보딩, 동의 후 역할별 진입, 지원자 PIN, 일반 빌드의 실증 도구·수집 차단을 확인했다. 실제 휴대전화 마이크, 당사자의 뜻 판단, 일반 STT 대비 효과, 실제 외부 AI 서비스 검증은 남아 있다. 따라서 기획서와 피드백의 모든 약속을 완료했다고 보고하지 않는다.

앱 버전은 [빌드 설정](../../app/build.gradle.kts#L38)에 0.3.2로 명시되어 있다. 아래 소스는 167f86f 기준이며 줄 번호는 후속 변경에 따라 달라질 수 있다.

### 첫 사용과 지원자 진입

첫 안내는 ① 평소 표현과 전할 뜻의 관계 ② 맞아요·아니에요·모르겠어요 반응 연습 ③ 내 뜻 전하기/표현 함께 준비하기 선택의 세 쪽으로 구성된다. 연습 답은 저장하거나 실제로 전달하지 않는다. 첫 이용자는 사용 역할과 보관 안내 두 항목을 확인한 뒤 학생 경로는 홈, 지원자 경로는 PIN 확인·설정을 거쳐 관리로 들어간다. 기존 동의 사용자는 안내와 동의를 매번 반복하지 않는다.

이는 화면 연습이지 당사자가 뜻을 이해했다는 평가 결과가 아니다. 맞는 답을 누르는 것만 익히게 하지 않고 다른 뜻·모름·중단이 실제 전달을 막는지 관찰해야 한다. ### 일반 서비스와 실증의 분리

현재 일반 빌드는 함께 관리의 실증 메뉴와 전역 실증 행동을 노출하지 않는다. 기록 수집과 A/B/C 조건도 기본으로 꺼져 있다. 공개 QA가 debug APK라는 이유만으로 내부 도구를 켜지 않으며, 별도 private 개발 빌드에서 명시적으로 선택한 경우에만 허용한다. 저장 경계에서도 도구가 꺼지면 동의 없는 상태로 처리한다.

기존 실증·교정 기록을 자동 삭제하지 않는다. 기록 보존과 사용자가 선택하는 현재 학생 자료 삭제·전체 삭제를 구분한다. 사용 화면에서 실증을 제외한 사실을 실증 완료나 원래 파일럿 약속의 달성으로 바꾸지 않는다. [기본 false 빌드 정책](../../app/build.gradle.kts#L24), [일반 빌드 기록 차단](../../app/src/main/java/kr/voicemate/malitda/ui/vm/SessionViewModel.kt#L691), [함께 관리 노출 조건](../../app/src/main/java/kr/voicemate/malitda/ui/v2/U07Entry.kt#L84)

## 4. 기획서·공식 피드백 대조

제공 PDF의 서비스 본문 1~8쪽과 연결된 기능명세서 v1.0의 18개 시트를 확인했다. 기능명세서는 2026-07-23 문서이며 이후 PDF와 다른 대상·기술·운영 범위가 있다. 상세 P0 90개와 시제품 요약 백로그 36개는 중복 관계다. 모두 더해 기능 수를 늘리거나 소스 연결 수를 구현률로 사용하지 않는다.

현재 앱은 원안의 Android SpeechRecognizer 대신 기기 내 Whisper·Vosk를 사용한다. 원안 API와 같은 구현으로 세지 않고 변경된 인식기·처리·실패 경로로 평가해야 한다. 뜻 후보는 등록표현과 비교해 찾는다. AI 그림 생성과 발화 의도 이해는 별도 기능이며, 실제 유료 생성 결과를 이번에 검증한 것은 아니다. ## 7. 검증 상태와 한계

소스 167f86f에서 단위 86개, 실패·오류·건너뜀 0건을 확인했다. ARM debug·R8 release 빌드와 lint 검사는 성공했다. lint 오류 0건, 경고 40건이며 경고까지 모두 없앴다는 의미는 아니다.

## 8. 남은 서비스 부족점과 다음 완료 조건

| 순서 | 부족점 | 다음 작업과 완료 조건 |
|---|---|---|
| 1 | 대상과 확인 가능 조건 | 진단명만으로 대상을 묶지 않고 STT 반환·그림/문장/TTS 이해·거절·유보·필요 도움을 확인한다. 누구에게 독립 사용이 가능하고 누구에게 AAC·지원이 필요한지 기록한다. |
| 2 | 실제 효용과 안전 근거 | 동의된 별도 실증에서 같은 사용자·과업의 기준선과 비교한다. 독립완료·재발화·수정·도움·시간·오추천·미승인 전달을 사용자별로 기록한다. 일반 서비스 빌드에서 수집을 자동으로 다시 켜지 않는다. |
| 3 | 실제 휴대전화 마이크·TTS | 제조사가 다른 실제 기기에서 권한 허용/거절·취소·소음·무결과·백그라운드·TTS 미지원·공유 취소를 확인한다. 에뮬레이터 화면 결과와 구분한다. |
| 4 | AI의 뜻 이해에 대한 기대 정리 | 현재는 등록 사전 기반 후보라는 설명을 유지한다. 등록되지 않은 표현·다의어·숫자·부정문·상황 변화에서 오추천을 분석한다. LLM 의미 추론은 데이터·안전·효용 검증이 필요한 후속 연구로 둔다. |
| 5 | 작성 중 초안 복원 | 현재 승인 스냅숏은 프로세스 종료 뒤 복원하지 않는다. 저장할 초안 범위와 보관 동의를 먼저 정하고, 복원 시 이전 전달 승인을 재사용하지 않는 인수조건을 만든다. 작성 폼 일부 상태 보존을 전체 초안 복원 완료로 세지 않는다. |
