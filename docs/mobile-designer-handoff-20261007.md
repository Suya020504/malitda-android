# 말잇다 모바일 디자이너 인계

2026년 10월 7일. 이 문서는 모바일 목표 시안과 현재 앱의 차이를 정리한 인계 기준이다. 새 시안이 APK에 모두 적용됐다는 뜻은 아니다.

**작업할 피그마:** [06 · 모바일 디자이너 인계](https://www.figma.com/design/RFGqsEDVAjLYPTwWhqOtN0?node-id=42-2839). 첫 화면은 [학생 홈](https://www.figma.com/design/RFGqsEDVAjLYPTwWhqOtN0?node-id=42-905), 좁은 화면은 [360폭 홈](https://www.figma.com/design/RFGqsEDVAjLYPTwWhqOtN0?node-id=42-2853)이다.

## 현재 상태와 작업 범위

기존 목업은 이미390×844 프레임42개였지만 큰 보드에 묶여 있었다. 이들을 모바일 인계 페이지에 정리하고, 공통 헤더·360폭6개·내부 카드/입력 폭·프로토타입 연결을 보완했다. 글자와 버튼·컴포넌트를 편집할 수 있다. 화면 전체를 이미지로 붙인 결과물이 아니다.

기준은 현재의 개인 의미 사전 흐름이다. 웹사이트의 초기 시안은 문장 입력·보정·보상 중심이고, 새 앱은 개인 표현의 뜻을 등록·확인·전달하는 흐름이다. 이전 기능과 브랜드 자산을 참고하되, 학생의 뜻 확인 절차를 생략하지 않는다.

공식 피드백의 “교정된 문장을 학생이 스스로 판단할 수 있는가”에 답하려면 글자만 보여주는 확인 화면으로 끝내지 않는다. 실제 학생이 구별할 수 있는 사진·그림·물건 선택·몸짓 등 확인·거절 방법을 현장에서 정한다. 읽기 능력이나 진단명만으로 확인 가능 여부를 가정하지 않는다.

| 마감 순서 | 모바일 목표 | 현재 APK0.2.0 | 디자이너가 넘길 것 |
|---|---|---|---|
| 1. 홈 | U01, U01-E | 말하기·카드·등록·내 표현이 본문에 모임. 목표 하단 메뉴는 미적용 | 홈/빈 상태·카드 수별 배치·하단 메뉴·상단 도움/설정 규칙 |
| 2. 뜻 확인 | U03, U06, U03-I/V | 선택·거절은 동작. 반복 안내와 이미지/버튼 높이는 목표와 차이 | 원문/카드 출처·그림 없는 상태·맞아요/다른 뜻·변경된 등록 복구 |
| 3. 전달 | U04, U04-F/S | 승인 후 소리·공유 동작. 공유 취소는 기존 화면 유지 | 보여주기·소리 오류·공유 복귀·다시 선택 상태 |
| 4. 함께 등록 | U07, U05, U05-E/M | 표현·뜻·그림·상황을 긴 한 화면에서 입력 | 입력/그림 선택/확인 구분·키보드·오류·미확인 저장. 단계 분리는 개발 협의 |
| 5. 등록 확인 | U10, U10-C | 확인 방법·지원자·체크 후 활성화. 긴 스크롤 | 확인 전 비활성·확인 후 활성·다른 확인 방법·돌아가기 |
| 6. 내 표현 | U08, U09, U11, U09-E/D/I | 상태 필터4개가 세로 라디오 목록. 수정·삭제·비활성 동작 | 목록/상세/미확인/수정/삭제/비활성/사용 재개 |

## 모바일 배치 기준

- 정본390×844, 최소 폭360, 추가 적용 시험412. 물리 픽셀과 앱의 논리 단위dp를 혼동하지 않는다.
- 부모 컨테이너의 크기에 맞춰 내용을 배치한다. 긴 문장은 높이가 늘어나게 하고, 한 줄로 억지로 축소하지 않는다.
- 상태바·화면 아래 시스템 영역을 확보한다. 스크롤 본문과 고정 탐색 영역이 서로 겹치지 않아야 한다.
- 키보드가 올라오면 현재 입력칸과 다음 동작을 볼 수 있어야 한다. OS 키보드 영역은 실제 기기에서 확인한다.
- 작은 화면은 본문을 스크롤할 수 있다. 버튼이나 사진의 오른쪽이 잘리는 결과를 축소 화면으로 제출하지 않는다.
- 큰 글자1.6배와2배, 긴 뜻200자·표현80자·상황120자·지원자80자의 배치를 추가 확인한다. 2배/최대 길이 전체 상태는 이번 시안에서 검증 완료한 항목이 아니다.
- 터치 영역48dp 이상을 유지하고, 학생 화면의 주 동작을 눈에 띄게 한다. 색만으로 선택·비활성·오류를 구분하지 않는다.

## 스타일 정본

최근 모바일 설계에서 선택한 **IBM Plex Sans KR**을 유지한다. 웹 홍보페이지의 Jua/Pretendard와 앱 조작 화면의 스타일을 혼동하지 않는다. 기존 폰트·색 변수·텍스트 스타일·컴포넌트를 우선 사용한다.

| 용도 | 피그마 스타일 | 기준 |
|---|---|---|
| 화면 제목 | 말잇다/Heading | 28, SemiBold |
| 전달할 뜻 | 말잇다/Meaning | 26, SemiBold |
| 설명 | 말잇다/Body | 18, Regular |
| 버튼 | 말잇다/Button | 20, SemiBold |
| 라벨/보조 | 말잇다/Label·Caption | 16 SemiBold·14 Regular |

원본 로고·캐릭터·의미 그림을 유지한다. 헤더 로고는120×34 FIT로 정리했고 원본 비율을 바꾸지 않았다. 색은 피그마의 color/* 변수와 primitive/* 값을 정본으로 맞춘다. 실제 앱의 일부 색·크기와 차이가 있으므로 개발자가 마감 시 토큰 대응표를 갱신한다.

## 동작과 데이터에서 바꾸지 않을 것

1. 인식한 원문과 등록한 뜻은 다른 값이다. 화면에서도 두 값을 구분한다.
2. 등록 확인과 이번에 전달할 뜻 확인은 다른 절차다. 등록해 둔 뜻도 사용할 때 다시 고른다.
3. 미확인·비활성인 뜻은 학생 카드와 후보에 표시하지 않는다.
4. 뜻·그림·학생이 바뀌면 이전 승인을 해제한다. 공유창을 닫았다고 전송 성공으로 보여주지 않는다.
5. 그림이 없거나 소리가 나오지 않아도 문장으로 뜻을 확인하고 화면으로 보여줄 수 있어야 한다.
6. 새 화면·새 상태·동작 변경은 화면ID와 사유를 정리해 앱 담당과 맞춘다. AI 담당자가 학생의 뜻을 자동 확정하는 흐름은 추가하지 않는다.

## 디자이너 전달물과 완료 조건

수정한 화면ID 목록, 공통 컴포넌트, 폰트/색/간격/반경/그림 비율, 자산 원본, 상태별 문구, 동작 변화, 남은 판단을 함께 넘긴다. 우선 핵심6개 흐름을 마감하고 나머지 예외를 같은 규칙으로 맞춘다. 원본 페이지를 덮어쓰기보다 이번 인계 페이지에서 작업해 비교 가능하게 둔다.

정본/360폭에서 버튼·입력·사진이 잘리지 않고, 클릭 목적지가 현재 인계 페이지의 올바른 상태로 이어져야 한다. 목업 검증은 실제 APK 동작 검증을 대신하지 않는다. 리터칭 후 앱 담당이 실제 휴대전화에서 글자·키보드·TalkBack·Switch Access·소리·공유를 확인한다.

별도 [화면 ID 전체 목록](handoff/mobile-screen-index-20261007.json)을 참고한다. 기존 와이어프레임은 같은 파일의 “03 · 와이어프레임” 페이지에 보존했다. 현재 앱/사이트 비교는 [디자인 검토](design-audit-20261007.md), AI 담당자의 변경 경계는 [AI 개발 명세](ai-implementation-spec-20261007.md)에 있다.
