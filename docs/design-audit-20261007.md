# 말잇다 사이트·APK 디자인 검토

2026년 10월 7일 현재 사이트와0.2.0-debug APK를 새로 열어 캡처했다. 결론은 **브랜드와 핵심 기능은 반영됐지만, 전체 디자인 마감 완료로 보기는 어렵다**는 것이다. 새 모바일 인계 페이지는 다음 적용 목표이며 현재 APK와 동일하지 않다.

## 확인한 화면

| 단계 | 확인한 내용 | 상태 |
|---|---|---|
| 1. 사이트 팀 영역 | 5개 역할·산출물·디자인북 연결 | 역할 구분은 명확. 버전/현재 검증 상태의 연결 필요 |
| 2. 사이트 모바일 시작·안내 | 390폭에서 `/app`을 조작 | 이미 모바일 체험이 있으나 화면PNG+클릭 영역 방식. 화면상 웹/모바일 선택기가 안내문·전화 위에 겹침 |
| 3. 사이트 동의 | 화면 안내 문구 | 외부 STT사용 문구가 현재 앱과 불일치. 동의 버튼은 누르지 않고 건너뜀 |
| 4. 현재 APK안내·홈 | 실제 앱의 글자·카드·조작 | 로고·캐릭터·핵심 이미지 재사용. 목표 하단 메뉴는 미적용 |
| 5. 현재 APK뜻 확인·전달 | 카드 선택·이번 승인·전달 | 핵심 동작은 연결. 안내 반복·본문 높이·보조 동작 밀도는 마감 필요 |
| 6. 현재 APK등록 | 입력창·그림·상황·확인 | 긴 한 화면의 스크롤. 키보드·단계 분리·현재 위치 안내 설계 필요 |
| 7. 피그마 정본·새 모바일 페이지 | 42개390×844와6개360폭 | 기존도 모바일 크기였음. 새 페이지에서 공통 헤더·폭·연결·컴포넌트·인계 기준 보완 |

## 반영된 것

원본 로고·캐릭터, 보라/민트 계열, 의미 그림4종, 새 의미 화면의 IBM Plex Sans KR, 큰 조작 영역과 스크롤, 미확인/확인/비활성 상태를 적용했다. 기능 검증과 브랜드 자산 재사용을 디자인 완성도 전체로 확대해 판단하지 않는다.

## 먼저 보완할 것

1. **탐색 구조:** 피그마 목표의 홈/내 표현/설정 하단 메뉴와 실제 앱의 본문 버튼·기어 메뉴를 맞춘다. 새로운 하단 메뉴를 추가할 때 상태와복귀도 함께 정의한다.
2. **등록 밀도:** 긴 한 화면을 입력/그림/학생 확인으로 어떻게 나눌지 정한다. 미확인 저장·오류·돌아가기·키보드에서 현재 입력이 유지돼야 한다.
3. **공통 스타일:** 새 의미 화면과 기존 안내·설정의 Jua/Pretendard·IBM계열 혼합을 정리한다. 최근 모바일 정본의 IBM을 기준으로 색·간격·크기·반경을 맞춘다.
4. **큰 글자와 긴 내용:** 실제 앱은 큰 글자/스크롤을 지원하지만 모든 목표 프레임의2배·최대 문자열 검증이 끝난 상태는 아니다. 정상/오류/빈 상태에서 모두 확인한다.
5. **설명문과 현재 구현:** 사이트는 Android SpeechRecognizer·자모/토큰 유사도·외부 STT를 설명하지만 현재 앱은 Whisper/Vosk·완전일치 의미 사전이다. 실제 구현/예정/검증 수준을 구분해 문구를 갱신한다.
6. **검증 주장:** 사이트의 WCAG준수·200%확대·TalkBack/SwitchAccess회귀검사 문구는 이번 개발 검증으로 뒷받침되지 않는다. 검증 기록을 붙이기 전에는 목표와검증 예정으로 표현한다.

## 판단에서 제외한 것

현재 앱의 영어 뜻은 가상 시험 자료다. 실제 사용자 자료로 보거나, 목업4카드와시험 앱1카드의 수 차이를 디자인 오류로 세지 않았다. 사이트 통계·경쟁 서비스 수치의 공식 원문 검증은 이번 화면 검토에 포함하지 않았다. 색상 대비·보조기술·실제 음성 출력·당사자 이해 전체의 준수를 선언하지 않는다.

캡처와 비교 그림은 별도 로컬 `모바일_AI_인계_20261007` 묶음에 넣는다. 코드 저장소에 실제 개인 사진·음성·금융/서명 자료를 포함하지 않는다. [모바일 디자이너 인계](mobile-designer-handoff-20261007.md)와 [AI개발 명세](ai-implementation-spec-20261007.md)를 같이 확인한다.
