# 말잇다 사용법과 실증 가이드

이 문서는 이용자와 지원자가 앱을 함께 준비하고, 진행자가 일반 사용과 실증을 구분해 운영하기 위한 안내입니다. 기존 홈과 **홈·내 표현·설정**의 세 탭을 유지하면서 추가한 개인 뜻 확인, 입력 대체, 접근성, 자료 관리와 실증 흐름을 설명합니다. 검증 중인 개발 소스를 기준으로 작성했으며, 설치할 APK의 버전·해시와 실제 시험 범위는 함께 제공하는 최신 검증명세에서 확인합니다.

## 1. 어떤 용도로 사용하는가

말잇다는 평소 쓰는 표현을 그 사람의 뜻과 연결하고, 본인이 확인한 뜻을 상대에게 전하는 의사소통 지원 앱입니다. 예를 들어 한 이용자의 ‘바람’을 ‘산책하러 가자’와 연결할 수 있습니다. 다른 이용자에게 같은 뜻을 자동 적용하지 않습니다. 발음 점수를 매기거나 치료 효과를 판정하지 않으며, AI가 의도를 추정해 바로 전달하지도 않습니다. 지원자는 이용자가 그림·글·소리 중 가능한 방법으로 뜻을 확인하고 거절하거나 중단할 수 있는지 먼저 살핍니다.

## 2. 처음 실행할 때

첫 안내에서 앱의 역할과 기기 내 저장·삭제 범위를 함께 읽고 두 확인 항목을 선택한 뒤 **‘확인하고 시작’**을 누릅니다. 이 확인은 실증 참여나 AI 외부 전송에 대한 동의를 포함하지 않습니다. 일반 말하기는 기기 내 Whisper·Vosk로 처리하며 원음 파일을 저장하지 않습니다. 마이크 권한은 **‘눌러서 말하기’**를 선택할 때 요청합니다. 허용하지 않거나 인식 준비가 끝나지 않았다면 카드와 **‘문장 직접 입력’**으로 계속 사용할 수 있습니다.

업데이트 후 **‘보관 자료를 열지 못했습니다’**가 표시되면 **‘다시 열기’**로 재시도합니다. 계속 열리지 않으면 **‘개발 프로젝트·복구 문의’**로 앱 버전과 발생 상황을 전달합니다. 복구할 자료가 있다면 Android의 저장공간 초기화나 앱 삭제를 먼저 진행하지 않습니다. 공개 문의에 이름·문장·사진·키를 첨부하지 않습니다.


검증용 패키지(`kr.voicemate.malitda.debug`)는 팀 배포본과 별도 앱입니다. 배포본의 개인 자료를 자동으로 읽지 않으므로 기존 앱을 삭제하지 않습니다. 배포본 자료를 유지한 업데이트는 개발팀의 동일 패키지·서명 빌드로 진행합니다.

## 3. 지원자 모드와 PIN

등록·학생 전환·설정·기록 관리 화면을 처음 열 때 지원자가 숫자 6자리 PIN을 정하고 한 번 더 입력합니다. 이후 잠긴 화면에서는 PIN을 확인해야 하며, 앱이 배경으로 이동하면 지원자 모드가 다시 잠깁니다. PIN을 여러 번 틀리면 재입력까지 기다려야 합니다. 잊어버렸다면 **‘기기 잠금으로 PIN 다시 정하기’**에서 Android의 기기 잠금 확인을 마친 뒤 새 PIN을 정합니다. 기기 잠금을 설정하지 않았다면 이 복구를 사용할 수 없습니다. PIN은 이 기기의 화면 잠금이며 보호자의 법적 권한이나 서버 계정을 인증하는 기능은 아닙니다. 지원자가 설정을 관리하더라도 이용자의 뜻을 대신 확정해서는 안 됩니다.

## 4. 세 탭의 역할

| 탭 | 주로 하는 일 |
|---|---|
| 홈 | 원형 마이크로 말하기, 그림 카드에서 뜻 고르기, 문장 직접 입력을 시작합니다. 음성 준비 상태와 개인 뜻의 보관 수를 확인합니다. |
| 내 표현 | 함께 확인한 뜻을 검색하고 분류·즐겨찾기·정렬을 사용합니다. 카드를 누르면 그 뜻을 다시 확인하며, 등록 내용 관리는 지원자 모드에서 진행합니다. |
| 설정 | 학생 전환, 함께 등록, 확인 방법과 접근성, 그림체, 실증, 개인정보·자료 관리를 준비합니다. |

**‘연습용 예시’**는 사용법을 익히는 자료입니다. 개인 표현으로 등록하고 본인 확인을 마친 기록과 구분합니다. 실제 실증에서는 참여자에게 맞는 뜻을 준비하고 연습 시도와 본실증을 나눕니다.

## 5. 개인 표현과 뜻을 함께 등록하기

지원자는 사용할 학생을 확인한 뒤 **‘지원자와 함께 등록’**에서 다음 순서로 준비합니다.

1. **평소 쓰는 표현**에 이용자가 실제로 사용하는 말을 입력합니다. 같은 뜻에 연결할 표현이 여러 개라면 쉼표로 구분합니다.
2. **전할 뜻**을 100자 이내로 적고 분류와 필요한 상황을 고릅니다. 같은 표현이라도 상황에 따라 뜻이 다르면 별도의 뜻으로 등록할 수 있습니다.
3. 그림이 필요하면 내장 그림이나 직접 고른 사진을 사용합니다. 그림 없이 글과 소리로 확인하는 방법도 가능합니다.
4. 바로 확인하려면 **‘학생과 뜻 확인하기’**, 나중에 확인하려면 **‘미확인으로 저장’**을 누릅니다.

개인 뜻은 학생별 최대 50개를 보관합니다. 미확인·사용 중지한 개인 뜻도 한도에 포함하며 앱이 넣은 연습 예시는 별도로 구분합니다. 저장하지 못한 경우 오류 안내를 확인하고 입력을 고쳐 다시 시도합니다. 등록한 표현을 일률적으로 짧게 고치거나 이용자의 의도보다 강한 문장으로 바꾸지 않습니다.

## 6. 미확인 보관과 본인 확인

**‘학생과 뜻 확인’**에서는 그림·문장·소리로 내용을 제시하고 학생의 실제 반응을 확인합니다. **‘맞는 뜻’**을 선택한 경우에만 **‘말로 답함’·‘가리켜 고름’·‘시선으로 고름’·‘정해 둔 신호’** 중 확인 방법을 함께 선택한 뒤 **‘확인한 뜻 사용하기’**를 누를 수 있습니다. ‘다른 뜻’, ‘모르겠음’, ‘응답 확인 안 됨’은 맞다는 응답으로 처리하지 않습니다. 판단하기 어렵다면 **‘미확인으로 두기’**를 선택하고 내 표현의 **‘미확인 보관함’**에서 다시 확인합니다. 뜻·그림·상황을 수정한 뒤에는 이전 확인을 그대로 사용하지 않고 다시 확인합니다.

## 7. 말하기에서 뜻 고르기

홈의 **‘눌러서 말하기’**를 누르고 천천히 말한 뒤 **‘말하기 끝내기’**를 누릅니다. 앱의 10초 타이머로 발화를 끊지 않습니다. 결과 화면에서 **들은 말의 원문**을 먼저 확인하고, 개인 설정에 따라 최대 1~3개 후보를 비교합니다. 원문을 그대로 확인하거나 직접 고칠 수도 있습니다. 개인 뜻을 골랐다면 그림·글·소리를 확인한 뒤 **‘맞아요’**를 선택합니다. **‘다른 뜻이에요’**는 다른 카드를 고르는 경로이고, **‘잘 모르겠어요’**는 전달을 보류하고 다시 확인하거나 멈추는 경로입니다. 후보가 없거나 인식 결과가 틀렸다면 카드·직접 입력·다시 말하기 중 편한 방법을 고릅니다.

## 8. 직접 입력과 수정

홈의 **‘문장 직접 입력’**이나 결과 화면의 **‘직접 고치기’**를 사용합니다. 원문은 임의로 잘라 넣지 않으며 직접 전할 문장은 200자 이내에서 확인합니다. 숫자나 부정 표현이 달라졌다는 안내가 나오면 시간·수량·거절의 뜻이 바뀌지 않았는지 살핍니다. **‘이 문장이 맞아요’**를 누른 뒤에 전달 화면으로 이동합니다. 다시 고치거나 다른 문장을 선택했다면 이전 승인은 취소되므로 새 문장을 다시 확인해야 합니다. 직접 입력한 문장을 개인 뜻 사전에 넣으려면 **‘내 표현에 함께 등록’**을 통해 지원자 등록과 본인 확인을 거칩니다.

## 9. 그림·소리·공유로 전달하기

전달 화면은 본인이 이번에 확인한 뜻이나 문장을 보여 줍니다. 상대에게 화면을 보여 주거나 **‘소리로 들려주기’**를 누릅니다. 오프라인 한국어 음성이 없으면 네트워크 음성으로 자동 전환하지 않고 그림·문장으로 안내합니다. 소리 데이터는 기기 설정에서 이용자가 직접 준비합니다. 소리를 멈출 때는 **‘소리 멈추기’**, 뜻을 바꿀 때는 **‘다시 고르기’** 또는 **‘다시 고치기 · 승인 취소’**를 사용합니다. 다른 앱으로 공유하거나 **‘문장 복사’**를 사용할 때도 확인한 문장만 대상으로 합니다. 앱 선택 창이 열렸거나 복사됐다는 사실은 상대에게 실제 전송되거나 이해됐다는 뜻이 아닙니다. 공유를 취소해도 문장을 확인한 뒤 다시 선택할 수 있습니다. 복사한 문장은 기기의 클립보드에도 들어가므로 공용 기기에서는 붙여 넣을 위치를 확인합니다.

## 10. 학생에게 편한 확인 방법 정하기

설정의 **‘확인 방법과 접근성’**에서 그림 먼저·글 먼저·소리 먼저, 후보 수, 비슷하게 들린 표현의 후보 제안 여부, 읽기 속도와 진동을 선택합니다. 이 항목은 현재 학생에게 적용합니다. ‘소리 먼저’는 확인 화면의 구성을 바꾸며, 자동으로 계속 소리를 재생하는 설정은 아닙니다. 앱 글자 크기는 200%까지 선택할 수 있고 휴대전화에서 확대해 둔 글자를 앱 설정 때문에 작게 만들지 않습니다. 테두리와 선택 강조도 함께 확인합니다. 보조기술은 앱 정보의 TalkBack·스위치 제어·Voice Access 안내를 참고하되, 이용할 실제 기기에서 시작·선택·중단 과업을 먼저 확인합니다. 모든 보조기술의 실기기 검증이 완료됐다는 의미는 아닙니다.

## 11. 기록 수와 삭제 범위 확인하기

설정의 **‘개인정보와 사용 안내’**에서 자료 관리 화면을 열고 현재 학생의 뜻·연결 표현·확인 이력·교정·실증·사진 수를 확인합니다. 한 뜻에 여러 표현이 연결되므로 항목 수를 합쳐 이용 횟수로 해석하지 않습니다. 개인 사전과 실증 기록은 암호화된 데이터베이스에 보관하며, 사진은 별도의 앱 전용 저장공간에 보관합니다. 다음 작업은 범위가 다르므로 확인 창을 읽고 선택합니다.

| 작업 | 삭제하거나 초기화하는 범위 | 남는 자료 |
|---|---|---|
| 현재 학생의 뜻 삭제 | 개인 뜻·연습 예시·연결 표현·확인 이력·이전 등록 문장·교정 이력과 필요 없어진 사진 | 학생·설정·실증 기록, 다른 학생이 참조하는 사진 |
| 현재 학생의 추천·교정 초기화 | 사용 횟수·개인 교정 이력 | 등록한 뜻·표현·그림·확인·실증 기록 |
| 현재 학생의 실증 기록 삭제 | 현재 학생의 실증 시도 기록 | 개인 뜻 사전·참여 설정과 다른 학생의 자료 |
| 기기 전체 자료 삭제 | 모든 학생의 자료·사진·실증·설정·PIN, 개발 시험용 음원·평가·공유 캐시 | 앱에 포함된 음성인식 모델 |

전체 삭제는 되돌릴 수 없습니다. 이미 다른 앱에 보낸 문장·CSV나 외부 서버 자료는 기기에서 삭제한다고 함께 지워지지 않습니다. 동의 철회와 참여 기록 삭제는 실증 설정에서도 별도로 진행할 수 있습니다.

## 12. 실증 전에 대상과 동의 준비하기

참여 범위가 정해지지 않았다면 치료사·지원자 검토와 연습부터 진행합니다. 실제 이용자가 참여할 경우에는 어떤 방법으로 뜻을 이해·선택·거절하는지, 중단 의사를 어떻게 표현하는지 먼저 확인합니다. 실증 참여는 일반 앱 사용과 별개이며 참여를 거절하거나 중단해도 앱을 사용할 수 있습니다. 기관의 설명·동의·필요한 보호자 동의·사진 촬영·보관 기간 절차를 먼저 준비합니다. 앱의 확인란은 그 절차를 대신하지 않습니다.

설정의 **‘실증 기록’ → ‘참여자·동의·과업 설정’**에서 실명 대신 `P001`처럼 영문 1자와 숫자 3~5자로 된 참여자 코드를 정합니다. 과업은 `T01`~`T999` 형식으로 구분하고, 참여자와 사전에 정한 목표 뜻을 연결합니다. 결과를 본 뒤 정답을 바꾸지 않습니다. 같은 비교에서는 같은 과업·목표·세트 버전을 사용하고, 목표가 바뀌면 새 버전으로 구분합니다. 본실증에는 확인·거절·중단 가능성 검토와 목표 뜻 설정이 필요합니다. 연습 시도는 반드시 연습으로 표시합니다.

## 13. A·B·C 조건으로 비교하기

| 조건 | 앱에서 비교하는 부분 | 진행할 때 지킬 것 |
|---|---|---|
| A · 기본 음성 전사 | 개인 표현 힌트를 사용하지 않고 인식한 원문을 확인합니다. 개인 뜻 후보는 제시하지 않습니다. | 원문을 확인한 뒤 전달합니다. 안전을 위해 카드·입력으로 전환할 수 있지만 그 전환을 숨기지 않습니다. |
| B · 개인 표현 후보 | 개인 사전의 뜻 후보를 비교하고 글을 우선해 확인합니다. | 같은 과업의 목표를 유지하고 제시된 후보에서 본인이 선택하게 합니다. |
| C · 개인별 확인 방법 | 개인 사전 후보를 그림·글·소리 중 미리 정한 선호 방식으로 확인합니다. | 지원자는 내용을 대신 확정하지 않고 필요한 도움만 제공합니다. |

앱은 참여자 번호에 따라 조건 순서를 제안하지만 조건을 자동으로 바꾸지는 않습니다. 진행자가 실제 조건을 확인하고 다음 시도를 준비합니다. 먼저 짧은 연습으로 사용법을 익힌 뒤 본실증을 진행하고, 세 조건 모두에서 본인 확인과 전달 승인을 유지합니다. 이 비교는 현장 사용성을 확인하기 위한 절차이며 임상적 치료 효과를 입증하는 시험으로 소개하지 않습니다.

## 14. 한 과업을 관찰하고 마치기

1. 과업 코드·목표·조건·연습 여부·주변 소음을 확인하고 홈에서 시작합니다.
2. 참여자의 말하기, 후보 선택, 다른 뜻 선택, 다시 말하기, 카드 전환, 직접 수정과 도움 여부를 관찰합니다. 진행자가 말을 대신 고르지 않습니다.
3. 전달 화면에서 **‘실증 응답 기록 · 지원자’**를 열어 상대가 뜻을 이해했는지 실제 반응을 보고 기록합니다. ‘상대가 이해함’은 앱이 전달 화면을 열었다는 이유로 선택하지 않습니다. 확인하지 못했다면 응답 없음으로 둡니다.
4. 참여자에게 선택·중단 가능성, 피로, 재사용 의향, 후보·소리 확인의 쉬운 정도를 묻습니다. 답변을 대신 추정하지 않으며 무응답은 별도로 남깁니다. 피로 항목은 점수가 높을수록 피로가 큰 뜻입니다.
5. 응답을 기록한 뒤 전달 화면으로 돌아와 **‘마치고 홈으로’**를 눌러 완료합니다. 취소·배경 전환 등으로 끝난 시도에 나중에 응답을 덧붙이지 않습니다.

참여자가 그만두려 하거나 피로·안전 문제가 보이면 바로 멈춥니다. **‘실증 잠시 중단’**에서 사유를 선택하고, 오전송을 관찰했다면 **‘오전송 관찰 · 실증 즉시 중단’**을 사용합니다. 앱의 피로 응답·연속 실패에 따른 중단 안내도 확인합니다. 자동 안내가 없더라도 진행자가 중단해야 하는 상황은 즉시 중단하며, 재개는 당사자의 의사와 상태를 다시 확인한 뒤 결정합니다.

## 15. 기록 수집과 CSV 공유 구분하기

실증 기록은 별도 참여 의사와 과업 설정을 확인한 경우에만 켭니다. 로컬 기록에는 참여자·과업 코드, 조건과 소요 시간, 선택·도움·중단 결과, 기기·환경과 선택형 면담 응답을 남깁니다. 실명·진단명·녹음·전사문·전달 문장은 실증 기록에 남기지 않습니다. 개인정보가 들어갈 수 있는 자유 면담 원문은 이 앱에 입력하지 않고 기관의 별도 보관 절차를 따릅니다.

**‘익명 CSV 확인’**에서는 현재 학생의 동의한 **본실증 완료 기록** 중 내보낼 수 있는 건수를 확인하고 **‘CSV 파일 공유’**를 선택합니다. 연습·중단 기록, 다른 학생의 기록, 이름·문장·절대시각·기기 정보·면담 내용은 CSV에 포함하지 않습니다. 참여자·과업 코드, 세트 버전, 조건, 소요 시간, 재시도·수정·도움·이해 등 수치만 내보냅니다. CSV의 `understood`는 `1`이 이해함, `0`이 이해하지 못함, `-1`이 미확인이며, 미확인을 실패로 합산하지 않습니다. 전달·첫 후보 선택 등의 수치는 상대 이해와 별개로 해석합니다. **‘참여 철회 및 이 학생 기록 삭제’**는 기기의 동의 설정과 기록을 지우지만 이미 공유한 사본까지 회수하지는 않습니다.

## 개발자 부록 A. 빌드 전에 모델과 소스 준비하기

다음 명령은 저장소 루트에서 실행합니다. Java 17, Android SDK 36, NDK `27.2.12479018`, CMake `3.22.1`이 준비돼 있어야 합니다. 대용량 모델은 Git에 포함하지 않으므로 새로 복제한 저장소에서 준비 단계 없이 APK를 만들지 않습니다.

```powershell
# Git Bash 등 Bash 실행 환경에서 whisper.cpp 1.9.4 소스를 준비합니다.
bash scripts/fetch-whisper.sh

# PowerShell에서 Whisper·Vosk 모델의 누락 여부와 해시를 확인합니다.
powershell -File scripts/prepare-models.ps1

# 실제 ARM 휴대전화용 디버그 APK를 빌드합니다.
.\gradlew.bat :app:assembleDebug -PsubmitAbis=arm
```

모델 파일의 기준은 `scripts/model-sha256.properties`입니다. 이미 승인된 모델 자산이 있다면 `prepare-models.ps1 -ExistingAssets <자산폴더>`로 복사·검증할 수 있습니다. APK 패키징에서도 모델의 존재 여부와 해시를 검사하며, 기존 파일이 기준과 다르다는 오류가 나면 원인을 확인한 뒤 처리합니다. 에뮬레이터는 해당 가상기기의 ABI에 맞는 별도 빌드를 사용합니다. 팀 배포용 서명·운영 서버·공개 배포는 디버그 빌드와 별도의 작업입니다.

## 개발자 부록 B. AI 그림의 모의 생성 시연

일반 사용 실증과 AI 그림 시연을 따로 진행합니다. 일반 사용에는 PC 서버가 필요하지 않습니다. 다음 순서는 디버그 APK와 **유료 생성기를 호출하지 않는 로컬 모의 서버**의 연결을 확인하기 위한 절차입니다. 실제 생성 서버의 패치와 연결 계약은 [R4 서버 안내](../r4-server/README.md)를 함께 확인합니다. 모의 서버는 모든 그림체에 기존 물 그림을 반환하며, 정해 둔 지연을 넣습니다. 이를 새 그림 생성 품질이나 실제 공급자 응답 속도로 해석하지 않습니다.

1. 저장소의 `docs/feedback-20261026/ai-demo/`에 `start_mock_server.py`와 `water.png`가 있는지 확인하고, 저장소 루트에서 실행합니다.

   ```powershell
   python docs/feedback-20261026/ai-demo/start_mock_server.py
   ```

2. PC에 연결한 시험 기기를 확인하고 디버그 APK를 설치한 뒤 포트를 연결합니다. 아래 설치 경로는 부록 A의 ARM 빌드 결과입니다.

   ```powershell
   adb devices
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   adb reverse tcp:8769 tcp:8769
   ```

3. 앱에서 지원자 PIN을 확인하고 현재 학생의 뜻 등록을 엽니다. 그림체를 선택한 뒤 등록할 뜻을 입력하고 그림 선택 화면으로 이동합니다. 기기 안의 `127.0.0.1:8769`가 `adb reverse`를 통해 PC의 같은 포트에 연결됩니다. 디버그 APK를 설치했는지, 서버가 켜져 있는지, 포트 연결이 남아 있는지 차례로 확인합니다.
4. 뜻 문장의 외부 전송·비용 안내를 확인하고 **생성할 때마다 별도로 동의**한 뒤 그림 만들기를 실행합니다. API 키를 APK나 채팅에 넣지 않습니다. 결과가 돌아오면 그림이 뜻과 맞는지 학생과 확인하고 등록을 마칩니다. 그림을 받았다는 사실만으로 개인 뜻을 확인 완료로 처리하지 않습니다.
5. 생성 중 그만두기를 시험합니다. 화면에서 결과 받기를 멈추더라도 이미 시작한 서버 작업이나 비용이 취소된다고 보장하지 않습니다. 실제 서버의 지연·오류에서는 같은 유료 요청을 무조건 다시 보내지 않습니다.
6. 끝나면 모의 서버를 종료하고 포트 연결을 제거합니다.

   ```powershell
   adb reverse --remove tcp:8769
   ```

기본 릴리스 구성은 그림 생성 주소가 비어 있으므로 모의 시연용 디버그 APK와 혼동하지 않습니다. 실제 유료 공급자 생성·운영 인증·비용·보관 정책과 당사자의 생성 그림 이해 정도는 이 모의 절차로 검증되지 않습니다. 실제 이용자에게 의사소통 효과가 있는지, 제조사가 다른 실제 휴대전화 두 종류에서 동작하는지도 별도의 검증이 필요합니다.

본 실증의 목표에는 연습 예시 대신 본인과 확인한 개인 뜻을 선택합니다. 예시 카드로 전달한 시도는 설정과 관계없이 연습으로 분류하며 효과 집계와 CSV에서 제외합니다.

## 실증 과업 완료와 중단을 구분

말하기 전후나 후보를 찾지 못한 상태에서도 **‘실증 과업 마치기 · 지원자’**로 기록 종료 화면에 들어갈 수 있습니다. 목표 뜻을 전하지 못했더라도 시험한 과업을 마쳤다면 관찰 응답을 고른 뒤 **‘과업 마침 기록’**을 선택합니다. 이 시도는 전달하지 못한 완료 과업으로 분모에 남습니다. 참여자 요청·피로·안전 때문에 멈춘 경우에는 **‘실증 중단으로 기록’**을 선택합니다. 둘을 같은 결과로 합치지 않습니다.

상대의 이해 응답이 있으면 이를 연속 실패 판단에 우선 사용합니다. 이해 응답이 없으면 목표 뜻의 관찰 결과를 참고하고, 둘 다 없으면 실패로 단정하지 않습니다. 완료할 때 다음 비교 조건의 권장 순서가 진행되며 조건 변경은 지원자가 확인합니다. 철회·실증 기록 삭제 때 기기의 임시 CSV도 정리합니다. 다른 학생의 원본 기록은 보존하고, 이미 외부로 복사한 파일은 앱에서 지울 수 없습니다.

## 화면 자료를 붙일 때

실제 APK에서 캡처한 이미지가 준비되면 다음 네 묶음을 문서에 추가합니다. 개인 이름·실제 문장·얼굴이 든 화면 대신 합성 시험 자료를 사용하며, 모의 그림에는 모의 시연임을 표시합니다.

- 시작 안내와 원형 홈, 세 탭이 한 흐름으로 이어지는 모습
- 함께 등록 → 학생 반응·확인 방법 → 이번 뜻 확인 → 전달의 순서
- 실증 준비의 조건·과업과 CSV 공유 범위 확인 화면
- PC 모의 서버 연결 상태 → 매회 동의 → 반환 그림 → 학생 확인의 순서

문서의 흐름 설명, 화면 캡처, 자동 시험과 실제 이용자 관찰은 서로 다른 증거입니다. 최종 안내에는 실행한 범위와 미실행 범위를 검증명세에 맞춰 구분합니다.
